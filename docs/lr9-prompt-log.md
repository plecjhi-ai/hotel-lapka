# Prompt Log — ЛР №9, «Готель Лапка»

> Нижче наведено структуровані інженерні завдання, використані для реалізації в поточному сеансі. Це не скріншоти внутрішнього чату VS Code.

## 1. Проєктування
**Завдання / промпт:** «На основі чинного лендингу “Готель Лапка” створити семантичну форму з полями ім’я, email, телефон, повідомлення та згода. Для кожного поля визначити правило, помилку, успішний стан; не змінювати решту секцій».
**Рішення ШІ:** форма з п’ятьма полями, видимими `label`, `aria-describedby`, окремими місцями для помилок.
**Що змінено:** замінено стару форму з 3 полями.
**Результат:** HTML інтегровано в сторінку.

## 2. Адаптивність
**Завдання / промпт:** «Стилізувати форму Tailwind за принципом mobile-first: одна колонка на телефонах, дві на md; зберегти кольори “Готелю Лапка”, focus-visible, кнопку не нижчу за 44 px».
**Рішення ШІ:** `grid-cols-1 md:grid-cols-2`, `md:col-span-2`, `min-h-12`, фокусні стани; брендові border-стани в CSS.
**Результат:** адаптивна структура в коді; перевірка різних ширин у браузері ще потрібна.

## 3. Валідація
**Завдання / промпт:** «Реалізувати окремі функції перевірки: ім’я ≥2; email — формат; телефон строго `+380` і 9 цифр; повідомлення ≥10; згода обов’язкова. Валідація input/blur/submit, повідомлення під полями, без сторонніх JS-бібліотек».
**Рішення ШІ:** `validateName`, `validateEmail`, `validatePhone`, `validateMessage`, `validateAgreement`, а також `showError`, `showSuccess`, `clearError`.
**Результат:** створено `js/validation.js`.

## 4. Модальне вікно та доступність
**Завдання / промпт:** «Додати доступне модальне вікно тільки після правильної клієнтської перевірки: aria-modal, закриття Escape, повернення фокусу, Tab усередині; не імітувати реальне надсилання».
**Рішення ШІ:** фокусована кнопка, Escape, focus trap, повернення фокусу після закриття, повідомлення про демонстраційний характер.
**Результат:** модальне вікно й події додані.

## 5. Код-аудит
**Завдання / промпт:** «Перевірити цілісність семантики, окремий JS-файл, збереження функцій ЛР №7, синтаксис JavaScript, правила регулярних виразів; зазначити межі статичного тестування».
**Рішення ШІ:** перевірено `node --check`, структуру HTML та посилання на локальні ресурси; браузерні тести та Vercel потрібно підтвердити окремо.
